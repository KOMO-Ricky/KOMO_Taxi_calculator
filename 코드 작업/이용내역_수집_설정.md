# 계산기 선택 내역 수집 — 적용 및 조회

## 무엇이 기록되는가

- 문자 신청과 무관하게 각 항목 저장/추천 적용/구성 초기화 등으로 저장된 선택 상태가 바뀔 때 기록한다. 모달에서 선택만 하고 저장하지 않은 변경은 보내지 않는다.
- GA4 `quote_selection_updated`: 지역, 차량, 연료, 납부 방식, 개월수, 수수료율 종류, 보험 유형, 조합/자차 여부, 옵션 개수·방식, 작업 항목, 완성 상태, 비교 진입 여부.
- GA4 `quote_option_changed`: 같은 차량에서 개별 옵션이 추가/해제될 때 옵션명과 selected 값. 차량 교체는 새 차량 선택 옵션을 기록하며 이전 차량 옵션 제거 이벤트를 별도로 생성하지 않는다.
- 시트 `계산기 이용내역`: 페이지별 임시번호와 구성 번호(1/2)로 같은 행을 갱신한다. 최신 선택 옵션 목록도 저장한다. 새로고침하면 새 번호가 생긴다. 이 번호는 사람 수나 GA 사용자 ID가 아니다.
- GA는 변경 이력이며 시트는 최신 상태다. 이벤트 횟수는 고객 수/견적 수와 같지 않다. 초기화하면 해당 구성의 시트 행도 초기화 상태로 갱신되므로 모든 과거 견적의 보존 용도는 아니다. 비교 진입 Y는 그 구성 슬롯에서 한 번 이상 비교에 들어갔다는 의미다.
- 이름·전화번호·자유입력 구성명·의견·보유자금·직접 입력 금액·견적 이미지·GA 클라이언트 ID·URL은 이 새 기록에 넣지 않는다. 기존 문자 신청 데이터 처리는 그대로다.

## 적용 순서

1. Apps Script의 기존 운영 코드에 `GAS_전체스크립트.gs`의 **saveCalculatorUsage_ 함수 전체**를 추가한다.
2. 기존 `doPost`의 JSON.parse 바로 뒤에 다음 분기를 추가한다. **doGet만 교체해서는 작동하지 않는다.**

```js
if (d.requestType === 'calculator_usage') return saveCalculatorUsage_(d);
```

3. 기존 문자 API 키·발신번호와 다른 최신 작업은 유지한다. SS_ID는 기존 스프레드시트 ID를 사용한다.
4. 배포 → 배포 관리 → 기존 계산기 웹앱 수정 → 새 버전 → 배포. 새 URL을 만드는 '새 배포'는 하지 않는다.
5. HTML 소스/index/preview를 GitHub에 커밋·푸시하여 웹페이지 배포.
6. 테스트 주소 `https://calculator.licen.co.kr/?analytics_debug=1`에서 계산 시작 후 면허 등 항목을 저장한다. 첫 유효 요청에 `계산기 이용내역` 탭과 헤더가 자동 생성된다. 미리 만들 필요 없다.
7. 동일 구성을 수정했을 때 같은 행의 갱신번호가 증가하는지 확인한다. 테스트 열은 Y로 표시된다. 통상 분석에는 N만 포함한다.

## GA4 설정

관리 → 데이터 표시 → 맞춤 정의 → 맞춤 측정기준 만들기에서 아래 필요한 항목을 이벤트 범위로 등록한다. 기존 5개 행동 이벤트와 complete_count는 유지된다.

| 표시 이름 예시 | 이벤트 매개변수 |
|---|---|
| 선택 지역 | region |
| 선택 차량 | car_name |
| 연료 | fuel |
| 구매 방식 | payment_type |
| 할부 개월수 | installment_months |
| 수수료율 종류 | rate_plan |
| 보험 유형 | insurance_type |
| 구성 상태 | quote_status |
| 비교 진입 여부 | comparison_viewed |
| 옵션 방식 | option_mode |
| 옵션명 | option_name |
| 옵션 선택 여부 | selected |

추가 필요 시 config_number, combine, self_cover, option_count, blackbox, blackbox_channels, hipass, pedal, roof_light도 등록할 수 있다. 전부 등록할 필요는 없다.

- rate_plan: base=기본, promo=프로모션, example=예시 수수료율.
- option_mode: individual=개별 선택, recommended=기존 추천 세트 포함, none=미포함.
- quote_status: in_progress=작성 중, complete=4항목 저장 완료.
- 자유 형식 탐색: 이벤트 이름을 quote_selection_updated로 필터하고 선택 지역/차량 등을 행, 총 사용자를 값으로 사용한다. 한 사용자가 여러 차종을 비교하면 여러 행에 포함되므로 행 합계는 전체 사용자 수와 다를 수 있다.
- 옵션 분석은 quote_option_changed + selected=true로 필터한다. 최종 선호 옵션은 시트 최신 행을 사용한다(중간 선택 후 해제된 항목도 GA 변경 이력에는 남는다).
- 아직 이 문서의 GA 관리 설정과 운영 수신 검증은 자동 실행하지 않았다.

## 운영상 유의점

- 새 기록도 기존 웹앱과 같은 no-cors 전송이다. 브라우저는 서버 저장 성공을 읽지 못한다. 네트워크 차단/연결 종료/Apps Script 한도 등으로 누락될 수 있다. 완전한 감사 로그나 확정 고객 수가 아니다.
- 500ms 동안 빠른 연속 변경을 합쳐 시트 쓰기를 줄이며, 백그라운드 전환 시 대기 중인 마지막 상태를 전송한다. 영구 재전송 큐는 두지 않는다.
- GAS에서 잠금과 증가하는 갱신번호로 중복·역순 도착을 처리한다. 미리 정의한 열만 기록하고 수식으로 해석될 수 있는 문자열을 이스케이프한다.
- 공개 웹앱 특성상 이 데이터는 사용자 브라우저가 제공하는 통계이며 인증된 거래 기록이 아니다. 현재 행 검색 방식은 소규모 검증용이며 트래픽이 커지면 별도 DB로 이전을 검토한다.
- 첫 화면/계산기/비교 화면 푸터에 수집 항목 안내와 추가 통계 수집 끄기를 제공한다. 끄기는 이 브라우저의 추가 이벤트·시트 전송에 적용하며 GA 기본 방문 통계나 이미 저장한 행을 삭제하지 않는다.
- 시트 보관기간 및 정기 정리 정책은 아직 확정하지 않았다. 임시번호만 쓴다고 완전 익명이라고 설명하지 않는다.

## 2026-09-23 추가 확정: 접속별 한 행

시트는 접속 기록번호 하나당 한 행으로 변경했다. 공통 4열(접속 기록번호/최초/최근/테스트) 뒤에 1번 구성 23열, 2번 구성 23열이 이어진다. 작성하지 않은 구성은 빈칸이다. 각 구성 저장은 자기 영역만 갱신하고 다른 구성 영역은 보존한다. GA4 선택 변경 수집은 그대로 유지된다. 저장 시점도 기존처럼 각 항목 저장 기준이며 비교 진입 시점으로 제한하지 않았다.

기존 두 행 구조의 '계산기 이용내역' 탭이 이미 있으면 보존하고 새 '계산기 이용내역(통합)' 탭에 이후 기록을 쓴다. 기존 기록을 자동 병합하지 않는다. 기존 탭이 없다면 '계산기 이용내역'에 한 행 구조를 생성한다. 이 변경은 GAS saveCalculatorUsage_ 함수 교체 및 기존 웹앱 새 버전 배포가 필요하다. 프런트 요청 형식은 그대로이므로 이미 배포한 프런트도 호환된다.
